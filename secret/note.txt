Secret = NƠI CẤT THÔNG TIN BÍ MẬT (password, token, api key, chứng chỉ SSL).

Giống hệt ConfigMap về cách dùng, chỉ khác Ở CHỖ CHỨA GÌ:

    ConfigMap : cấu hình CÔNG KHAI  (port, url, log level, feature flag)
    Secret    : thông tin BÍ MẬT    (password, token, key, certificate)


1. SECRET CÓ THỰC SỰ "BÍ MẬT" KHÔNG? - HIỂU ĐÚNG NGAY TỪ ĐẦU
--------------------------------------------------
⚠️ Secret CHỈ mã hóa base64. Mà base64 KHÔNG PHẢI mã hóa - chỉ là ĐỔI CÁCH VIẾT.
   Ai cũng giải ngược lại được trong 1 giây:

        echo "MTIzNDU2" | base64 -d      ->  123456

=> Secret KHÔNG an toàn hơn ConfigMap bao nhiêu. Nó chỉ giúp:
        - Không lộ password khi lỡ in log / chụp màn hình
        - kubectl get secret KHÔNG hiện giá trị ra như ConfigMap
        - Đánh dấu "đây là dữ liệu nhạy cảm" -> phân quyền RBAC riêng được
        - K8s tự động không ghi Secret vào log sự kiện

Muốn AN TOÀN THẬT, cần thêm:
        - Bật Encryption at Rest (mã hóa trong etcd)
        - Phân quyền RBAC chặt (ai được đọc Secret nào)
        - Hoặc dùng công cụ ngoài: HashiCorp Vault, Sealed Secrets, External Secrets

⛔ TUYỆT ĐỐI KHÔNG commit file secret.yaml có password thật lên git.
   Thêm vào .gitignore, hoặc dùng Sealed Secrets (mã hóa được phép đưa lên git).


2. HAI CÁCH GHI GIÁ TRỊ: data vs stringData
--------------------------------------------------
- data        : PHẢI tự mã hóa base64 trước khi ghi vào
        password: MTIzNDU2

  Tự tạo chuỗi base64:
        echo -n "123456" | base64            ->  MTIzNDU2
        (-n rất quan trọng: thiếu nó sẽ dính thêm ký tự xuống dòng -> sai password)

- stringData  : ghi CHỮ THƯỜNG, k8s TỰ mã hóa giúp   <- DỄ HƠN, NÊN DÙNG
        password: "123456"

  Lưu ý: apply xong, đọc lại bằng -o yaml sẽ thấy nó đã chuyển thành data (base64).


3. CÁC LOẠI SECRET (trường type)
--------------------------------------------------
- Opaque                              : mặc định, tự do đặt key/value (hay dùng nhất)
- kubernetes.io/dockerconfigjson      : mật khẩu đăng nhập registry để pull image private
- kubernetes.io/tls                   : chứng chỉ HTTPS (Ingress dùng cái này)
                                        bắt buộc 2 key: tls.crt và tls.key
- kubernetes.io/basic-auth            : cặp username / password
- kubernetes.io/service-account-token : token cho ServiceAccount (k8s tự tạo)


4. GẮN VÀO POD - 3 KIỂU (y hệt ConfigMap)
--------------------------------------------------
KIỂU A - lấy TỪNG biến (an toàn nhất, nên dùng):

        env:
        - name: DB_PASSWORD             # tên biến trong container
          valueFrom:
            secretKeyRef:               # <- khác ConfigMap ở chữ "secret"
              name: db-secret           # <- metadata.name của Secret
              key: password             # <- key trong data / stringData


KIỂU B - nạp HẾT thành biến môi trường:

        envFrom:
        - secretRef:
            name: db-secret


KIỂU C - gắn thành FILE (dùng cho chứng chỉ SSL, key file):

        volumeMounts:
        - name: secret-volume
          mountPath: /etc/secrets
          readOnly: true                # nên bật, tránh ghi đè nhầm
        ...
        volumes:
        - name: secret-volume
          secret:
            secretName: db-secret       # ⚠️ ở đây là "secretName", KHÔNG phải "name"
                                        #    (ConfigMap thì viết là "name" - dễ nhầm)

=> Kiểu C AN TOÀN HƠN kiểu A/B, vì biến môi trường dễ bị lộ:
   lỡ in ra log, hoặc chạy `env` trong container là thấy hết.


5. KHÁC BIỆT SO VỚI CONFIGMAP - BẢNG SO SÁNH
--------------------------------------------------
                        ConfigMap              Secret
    kind:               ConfigMap              Secret
    lưu dạng:           chữ thường             base64
    ghi thẳng chữ:      data                   stringData
    lấy 1 biến:         configMapKeyRef        secretKeyRef
    lấy hết biến:       configMapRef           secretRef
    trong volumes:      configMap.name         secret.secretName
    xem giá trị:        get cm -o yaml (thấy)  phải base64 -d mới đọc được
    giới hạn:           1 MB                   1 MB


6. LỆNH HAY DÙNG
--------------------------------------------------
    kubectl apply -f secret.yaml
    kubectl get secret                                  # KHÔNG hiện giá trị, chỉ hiện tên + số key
    kubectl describe secret db-secret                   # cũng chỉ hiện số byte, không hiện value

    # đọc ngược giá trị thật
    kubectl get secret db-secret -o jsonpath='{.data.password}' | base64 -d

    # tạo nhanh không cần file YAML (AN TOÀN HƠN - không để password trong file)
    kubectl create secret generic db-secret \
        --from-literal=username=admin \
        --from-literal=password=123456

    # tạo secret chứng chỉ TLS cho Ingress
    kubectl create secret tls my-tls --cert=tls.crt --key=tls.key

    # tạo secret để pull image private
    kubectl create secret docker-registry regcred \
        --docker-server=... --docker-username=... --docker-password=...

    # mã hóa / giải mã thủ công
    echo -n "123456" | base64                           # -> MTIzNDU2
    echo "MTIzNDU2" | base64 -d                         # -> 123456

    # sửa Secret xong PHẢI restart Pod (giống ConfigMap)
    kubectl rollout restart deployment <ten-deployment>

    kubectl delete -f secret.yaml


7. LƯU Ý
--------------------------------------------------
- Secret phải TỒN TẠI TRƯỚC khi Pod chạy, và PHẢI CÙNG NAMESPACE với Pod.
  Gọi tên không có thật -> Pod kẹt ở CreateContainerConfigError.
- Sửa Secret rồi, Pod KHÔNG tự cập nhật nếu gắn kiểu env -> phải rollout restart.
- Đừng dùng lệnh `kubectl create secret` kèm password ngay trên terminal ở máy chung,
  vì nó bị lưu lại trong lịch sử shell (~/.zsh_history).
- Giới hạn 1 MB.


8. GHI NHỚ NGẮN
--------------------------------------------------
    Secret = ConfigMap dành cho dữ liệu nhạy cảm.

    Cách dùng giống hệt, chỉ đổi:  configMap -> secret
    Nhớ 2 điều quan trọng nhất:
        1. base64 KHÔNG phải mã hóa - đừng tưởng là an toàn
        2. ĐỪNG đẩy password thật lên git
